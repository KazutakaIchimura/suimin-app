# 単体/中間/E2Eの切り分けと骨抜き禁止

## 種別と実行コマンド

| 種別 | ツール | 置き場所 | 実行 | 何を守るか |
| --- | --- | --- | --- | --- |
| 単体 | Jest（`jest-expo`） | `tests/unit`（srcの構造を再現） | `npm test -- tests/unit` | ロジックの境界値・異常系 |
| 中間 | Jest ＋ React Native Testing Library | `tests/integration` | `npm test -- tests/integration` | DBをまたぐ制御フロー・受け口層（画面・フック）の薄い制御 |
| E2E | Maestro（YAMLのフロー） | `tests/e2e` | `maestro test tests/e2e`（開発ビルドを入れたエミュレータ・実機が必要） | 主要フロー・権限・状態遷移 |

- 単体の置き場所はsrcのパスを再現する（例：`src/features/smart-alarm/smart-alarm.service.ts` → `tests/unit/features/smart-alarm/smart-alarm.service.test.ts`）
- テストファイル名は `<対象ファイル名>.test.ts(x)`、Maestro のフローは `<フロー名>.yaml` とする
- 単体・中間は開発コンテナ内で実行できる。E2E はコンテナ内では実行できないため、エミュレータ・実機を接続した環境（または EAS のクラウド実行）で実行する
- E2Eは実行前にシードデータの投入とアプリ起動が要る（後述）

## 単体・中間・E2Eの切り分け
E2Eで検証する
- ユーザーフローの完走（ヘルスケアの許可 → 睡眠記録の表示、アラーム設定 → 鳴動）
- 権限（ヘルスケアの読み取り許可がない・拒否されたときの案内）
- 複数画面をまたぐ結合動作、状態遷移
- 実際のヘルスケア・アラームとの連携を含むフロー（モックしない）

単体で検証する
- 純粋な計算・整形・バリデーション（外部I/Oなし）。例：睡眠サイクルの計算、実績からの推定、日付をまたぐ睡眠の扱い
- E2Eでは網羅しにくい細かな実装

中間テストに落とす（`tests/integration`）
- DBをまたぐ制御フロー。Drizzle はテスト用の SQLite（Node 上で動くもの）に実際のマイグレーションを適用して、本物のSQLを通す
- 受け口層（画面の表示・操作、フックの状態遷移）の薄い制御。ヘルスケア・アラームのネイティブライブラリは `jest.mock` でテスト用の実装に差し替えてよい
- E2Eにするとモックが増えすぎて、実装詳細に張り付くケース

## E2Eのシードデータ
E2Eは、固定のデータを入れたデータベースに対して走らせる。ヘルスケアの睡眠データは、テスト用の端末（エミュレータ）にあらかじめ投入しておく

- シードは1つの定義ファイル（`tests/e2e/seed/` 配下）に集約し、テスト内で独自のマジック値を作らない
- 最低限用意する：睡眠実績がない状態、数日分ある状態、推定に足りる日数（例：14日分）ある状態
- 実行の流れ：シード投入 → アプリ起動
- 読み取り専用のテストは既存シードを使う。変更を伴うテストは専用データを準備処理（Jest は `beforeEach`、Maestro はフロー冒頭の `runFlow`）で作り、後始末する

## 骨抜き禁止

次のようなテストは、何も守っていないので書かない。

- **存在確認だけのアサーション**：`toBeDefined()` / `not.toBeNull()` だけ、画面に要素があるだけを確かめ、中身を検証しない
- **常に成功するモック**：テスト対象のロジックそのものを固定値を返すモックに差し替える（本物が壊れても通る）。モックしてよいのは外部I/O（ヘルスケア・アラーム・通知）の境界だけ
  - OS から来る値（`react-native` の `Platform.OS`・`AppState` など）と、DB への入力データ（テスト用DBへの差し替え・失敗を起こすための壊れたマイグレーション）も境界に含める。アプリ内のロジックは差し替えない
- **条件付きスキップ**：環境や権限がないときに黙って return し、成功扱いにする（スキップするなら `it.skip` に理由を書いて明示的にスキップとして報告させる）

- E2Eでアプリ内部の層をモックしない
- 新規テストは先にREDを確認してから実装する

## テストの独立性
- 変更を伴うテストは、自分専用のデータを作り、終了時に片づける（読み取り専用のテストは既存シードを使ってよい）
- 他のテストが作ったデータ・実行順序に依存しない
- 現在時刻に依存しない。時刻は引数で渡すか、`jest.useFakeTimers()` と `jest.setSystemTime()` で固定する
- 固定時間のスリープで待たない。`findBy*` や `waitFor`（Maestro は `extendedWaitUntil`）など、条件が満たされるまで待つ仕組みを使う
- 画面要素を選ぶときは、ロール・ラベル（`accessibilityLabel`）・テキスト・`testID` を優先し、コンポーネントの入れ子構造やスタイルに依存しない
