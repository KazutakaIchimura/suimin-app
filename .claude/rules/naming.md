# ファイル名・フォルダ名の命名規則

## 使ってよい文字
- ファイル名・フォルダ名は半角英数字と `-` `_` `.` のみ使う
- 日本語（ひらがな・カタカナ・漢字）、全角文字（全角数字・全角スペースを含む）、半角スペースは使わない
- 対象は「名前」だけ。ファイルの中身（ドキュメント本文・コードコメント・コミットメッセージ）は日本語でよい

理由：パスに日本語・全角・空白が含まれると、ビルドツール・テストランナー・CI（Linux）で文字化けや解決失敗を起こすため

### 例外：expo-router の画面ルート
- `src/app/` の中に限り、expo-router がファイル名で意味を決める記号を使ってよい
  - `[param]`（URL の値を受け取る画面。例：`src/app/sleep/[date].tsx`）、`[...param]`（残りのパスをまとめて受け取る）
  - `(group)`（URL に出ないフォルダ。例：`src/app/(tabs)/`）
  - `+not-found.tsx` などの `+` で始まる特別なファイル
- 記号の中の名前（`param`・`group` など）は、上の「使ってよい文字」に従う
- `src/app/` の外では使わない

理由：expo-router はこれらの記号をファイル名の規約として要求し、代わりの書き方がないため

## 連番を振る場合
- 半角数字・ゼロ埋め2桁で振る（例：`01_login.md`、`02_signup.md`）
- ファイル一覧で作成順どおりに並ぶようにするため（`10_` が `2_` より前に並ぶのを防ぐ）

## 例
```
✕ ログイン設計.md      ✕ １_login.md      ✕ login design.md
☑ 01_login.md          ☑ user-profile/    ☑ invoice.service.ts
```

## ブランチ名
- `feature/` + 対象の設計書名（拡張子 `.md` を除き、`_` を `-` に置き換える）
  - 例：`docs/features/01_login.md` → `feature/01-login`
- 既存機能の修正も、対象の設計書名から同じ規則で付ける
- 同名のブランチが残っている場合は、枝番を半角数字・ゼロ埋め2桁で付ける（例：`feature/01-login-02`）
- 使ってよい文字はファイル名と同じ（半角英数字と `-` `_` `.`、区切りの `/`）

理由：ブランチ名から対応する設計書をすぐ引けるようにするため

### 設計書を伴わない変更
- 開発ルール・スキル・エージェント・CLAUDE.md・設定ファイルなど、アプリの機能に関わらない変更は `chore/` + 変更内容を表す英小文字の短い名前（単語は `-` でつなぐ）
  - 例：`chore/update-dev-rules`、`chore/fix-review-rules`
- この変更には設計書を作らず、`ai-review` の対象外とする
- 同名のブランチが残っている場合の枝番は `feature/` と同じ（例：`chore/update-dev-rules-02`）
