## ルール
1. 業務コードで標準出力・標準エラー出力へ直接書き込まない（言語標準の print 系・console 系の関数を直接呼ばない）。ログは `src/lib/` 配下の共通ログ関数を経由する
   （直書きすると requestId の付与とマスク処理を迂回してしまうため）
2. ラップするのは外部IO・副作用・失敗しうる処理だけ（DB、外部API、通知送信）。純粋関数はラップしない（ノイズになるだけ）
3. エラーは記録したあと必ず呼び出し元へ伝播させる（再スロー・エラー値の返却など、言語の流儀に従う）。握りつぶして正常形を返さない
4. 引数は要約だけを記録する（IDなど）。オブジェクトを丸ごと渡さない
5. info を出すのは外部APIの成功・1秒を超える処理・重要イベントだけ。それ以外の成功は黙る（ログのノイズを増やさない）

## 標準キー
| キー | 内容 |
| --- | --- |
| name | domain.function 形式（例：invoice.createDraft） |
| userId | 関連する主体のID |
| requestId | リクエスト単位の相関ID |
| err | エラー種別・メッセージ・スタックトレースに整形 |
| ms | 所要時間 |

## 秘密値をログに渡さない
認証トークン・パスワード再設定リンク・APIキー・カード/口座情報・生の個人情報は、いかなるログにも書かない

```text
✕ 標準出力へ直接、再設定リンクそのものを書き出す
   print("reset link generated", resetLink)      ← リンクは実質パスワード。ログに残してはいけない

☑ 共通ログ関数経由で、要約だけを記録する
   log.info("auth.sendResetLink", { emailDomain: <メールアドレスのドメイン部分> })   ← リンク自体は記録しない
```
